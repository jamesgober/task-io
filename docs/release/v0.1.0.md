# task-io v0.1.0 - Scaffold

**The repository, the plan, and the performance contract.** v0.1.0 sets up the crate in the portfolio template and writes down the design before any code: what task-io owns, what it leaves to other crates, the benchmarks it has to win, and how ideas are tested before they are built. There is no functional code in this release.

## What is task-io?

The task dispatch pipeline for the `-io` crates: workers that pull jobs from bounded priority lanes, with delays, cron, retries with backoff, dead letters, idempotency keys, leases, and durable stores, then dispatch across nodes. Its first consumers are the web stack (emails, cleanup, session-expiry sweeps) and smtp-net (retries and dead letters for outgoing mail).

## What's in 0.1.0

- The crate manifest: edition 2024, MSRV 1.85, no dependencies, `Apache-2.0 OR MIT`.
- CI on Linux, macOS, and Windows, on stable and 1.85, plus `cargo audit` and `cargo deny`.
- `dev/PLAN.md`: scope, mandates, planned architecture and API, failure model, security responsibilities, ecosystem, open decisions, and the decision log.
- `dev/BENCHMARKS.md`: 20 workloads across workers and dispatch, delays and cron, retries, idempotency, durability, and a soak, the competitors for each, the measurement protocol, and the gate (at least 1.20 times the best competitor).
- `dev/RESEARCH.md`: the R&D program and the ideas to test.
- `dev/DIRECTIVES.md` (engineering law, definition of done, invariants) and `dev/ROADMAP.md` (phases with exit criteria).

## What's next

`0.2.0` builds the competitor harness and measures every competitor, so each target becomes a number; runs the experiments; and locks the public API. `0.3.0` delivers the local pipeline, `0.4.0` the durable store.
