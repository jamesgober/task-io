# task-io v0.1.0 - Scaffold

**The repository, the plan, and the performance contract.** v0.1.0 sets up the crate in the portfolio template and writes down the design before any code: what task-io owns, what it leaves to other crates, the benchmarks it has to win, and how ideas are tested before they are built. There is no functional code in this release.

## What is task-io?

The task runtime for the `-io` crates: one scheduler for async tasks, blocking calls, and CPU fork-join work, with timers, cancellation, panic isolation, and monitors built in, then durable jobs and dispatch across nodes. Actors and spawns are separate crates built on top of it. Its consumers are the web stack (background jobs), smtp-net (retries and dead letters), the Hive DB executor (morsel scheduling with locality hints), and the LexerSketch runtime (`spawn` in scripts).

## What's in 0.1.0

- The crate manifest: edition 2024, MSRV 1.85, no dependencies, `Apache-2.0 OR MIT`.
- CI on Linux, macOS, and Windows, on stable and 1.85, plus `cargo audit` and `cargo deny`.
- `dev/PLAN.md`: scope, mandates, planned architecture and API, failure model, security responsibilities, ecosystem, open decisions, and the decision log.
- `dev/BENCHMARKS.md`: 28 workloads across the executor, timers, channels, jobs, and stress, the competitors for each, the measurement protocol, and the gate (at least 1.20 times the best competitor).
- `dev/RESEARCH.md`: the R&D program and the ideas to test.
- `dev/DIRECTIVES.md` (engineering law, definition of done, invariants) and `dev/ROADMAP.md` (phases with exit criteria).
